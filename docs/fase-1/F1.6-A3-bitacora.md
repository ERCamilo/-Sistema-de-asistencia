## Resumen evaluable

A3 incorpora una ruta scoped en `PayrollService.calculateEmployeePayroll`: captura contexto y `projectId` sincrónicamente antes del primer `await`, consulta configuración solo con el `capturedProjectId` y falla de forma cerrada si la lectura retorna un valor falsy o falla. Con el flag OFF, la ruta legacy conserva su retorno síncrono y su cuerpo de cálculo; con el flag ON, la operación retorna una `Promise` y calcula únicamente con las colecciones clonadas del contexto, `ctx.getAttendance()` y la configuración resuelta para el proyecto capturado.

`PayrollPeriod` añade helpers basados en contexto para resolución de período, asistencia presente y selección de empleados. `getPayrollEmployeesForPeriod(state, ...)` ya captura el contexto y usa la selección scoped cuando el flag está ON. La resolución de configuración de período existe a nivel de helper, pero **no está demostrada a través de todos los callers productivos ni constituye wiring end-to-end de UI/runtime**.

El snapshot ON es un **snapshot deep-cloned con congelamiento de primer nivel**: clona profundamente empleados, posiciones, líderes, asistencia y settings; congela las colecciones, mapas y registros de primer nivel resultantes. No congela recursivamente todos los objetos anidados. `exportConfig` conserva la referencia original y el mapa clonado completo de asistencia sigue expuesto; el aislamiento de lectura se aplica mediante `ctx.getAttendance()`.

## 2. Contratos exactos

### 2.1 Captura y asincronía

- `PayrollService.calculateEmployeePayroll()` captura `PayrollProjectContext` y `capturedProjectId` sincrónicamente antes del primer `await`.
- Con flag OFF retorna el resultado legacy de forma síncrona y conserva el cuerpo de cálculo existente.
- Con flag ON retorna una `Promise`; la consulta de configuración usa exclusivamente el ID capturado, aunque el proyecto activo cambie durante la espera.
- `resolveScopedPayrollContext()` y `resolveScopedPayrollPeriodContext()` siguen el mismo contrato de captura previa.

### 2.2 Configuración y fail-closed

- Si el store retorna `null`, otro valor falsy o falla, la ruta scoped lanza `Payroll config unavailable for project "<id>"`; no vuelve a `state.settings` como configuración general.
- Esta frontera **no valida el esquema de una configuración truthy malformada**. A3 confía en el contrato de normalización/validación de A2 para configuraciones persistidas correctamente.
- El cálculo consume `regularHoursPerDay`, `overtimeFactor`, `holidayFactor`, `holidays` y `payPeriod` donde el helper correspondiente está conectado.
- `restDayFactor` no forma parte de `projectPayrollConfigs` A2. Continúa resolviéndose por posición → líder → settings capturados → default.
- `payrollDefaults` y `defaultDeductionPercentage` existen en A2, pero todavía no son consumidos por el cálculo scoped A3.

### 2.3 Datos scoped y asistencia

- El cálculo scoped busca empleados, posiciones y líderes únicamente en el contexto capturado.
- La asistencia se consulta mediante `ctx.getAttendance(employeeId, dateKey)`; `PayrollService` y `PayrollPeriod` no importan ni consumen `buildAttendanceIndex` RAW.
- El snapshot conserva el mapa clonado completo de asistencia en `ctx.attendance`/`getAttendanceMap()`. La protección de proyecto se aplica en `ctx.getAttendance()`, no eliminando físicamente registros ajenos del mapa expuesto.
- Dos fichas con el número visible `#12` siguen siendo independientes por `employeeId` y `projectId`.

### 2.4 Snapshot y congelamiento

- Empleados, posiciones, líderes, asistencia y settings se clonan profundamente al capturar el contexto ON.
- Los arrays/mapas contenedores y cada registro superior clonado se congelan con `Object.freeze`.
- Los objetos anidados dentro de cada registro son copias independientes, pero no reciben congelamiento recursivo.
- `exportConfig` no se clona ni se congela: conserva la referencia original. Su saneamiento H-05 sigue pendiente fuera de A3.

### 2.5 Alcance real de `PayrollPeriod`

- `getPayrollEmployeesForPeriod(state, ...)` captura contexto y deriva la selección scoped con flag ON.
- `getPresentAttendanceInPeriodWithContext()` usa `ctx.getAttendance()`.
- `resolvePayrollPeriodWithContext()` puede resolver `config.payPeriod`, pero A3 no demuestra que todos los callers productivos usen este helper.
- Por ello, A3 no debe describirse como wiring completo end-to-end de UI/runtime.

  3. El cambio A→B invalida selección temporal, preview, período y caché de sesión; B→A reconstruye A.
  4. Una preview async iniciada en A permanece en A mientras una preview nueva usa B.
  5. Con flag OFF, la UI legacy permanece exacta.
  6. No se habilitan cierres, préstamos, ajustes persistidos, historial ni exportación final.
  7. No se trabaja H-05 ni se amplía la persistencia de `exportConfig`.
