## 1. Frozen Schema & Transport Neutrality

- Envelope and row byte/shape semantics for `attendance-submission/v1` remain strictly unchanged as defined in `docs/fase-3/F3.4-attendance-submission.md`.
- Transport-neutral intake: `AttendanceSubmissionInboxStore` accepts both bare JSON strings and structured JavaScript payload objects (`importSubmission`), allowing reception from P2P, file, clipboard, or future transports.

## 2. Canonical SA IndexedDB Migration (v20 → v21)

- **Database Version**: Bumped from 20 to 21 in `IndexedDBService`.
- **New Store**: `attendanceSubmissionInbox`
  - `keyPath`: `'key'` (`encodeURIComponent(saProjectId) + '|' + encodeURIComponent(submissionId)`)
  - **Indexes**:
    - `status` (`status`, `{ unique: false }`)
    - `saProjectId` (`saProjectId`, `{ unique: false }`)
    - `workDate` (`workDate`, `{ unique: false }`)
    - `receivedAt` (`receivedAt`, `{ unique: false }`)
- **Migration Discipline**:
  - Upgrading an existing v20 database preserves all existing object stores and records (employees, positions, leaders, attendance, settings, projects, payrollClosures, etc.) intact without data loss.
  - Verified by real IndexedDB migration test `IndexedDBUpgradeV20ToV21.test.js`.

## 3. Persistent Draft Lifecycle (`AttendanceSubmissionInboxStore`)

- **Zero Attendance Writes on Receive**:
  - The inbox store operates exclusively on `attendanceSubmissionInbox`.
  - It NEVER writes to the official `attendance` store, touches global `state`, or applies records automatically.
- **Draft Lifecycle Extensions**:
  - `list(filter = null)`: Filter by `{ saProjectId, workDate, status }`.
  - `listByProject(saProjectId)`: List drafts for a specific project.
  - `updateStatus(saProjectId, submissionId, nextStatus, { blockers, metadata })`: Update draft status (e.g. `'pending'`, `'reviewed'`, `'consolidated'`) and review metadata while preserving original timestamps, `bodyHash`, and `sourceSnapshot`.
  - `delete(saProjectId, submissionId)`: Discard drafts when requested.
  - `importSubmission(input, options)`: Polymorphic entry point accepting object or string.

## 4. Pure Cross-Mini Consolidation (`AttendanceConsolidation.js`)

- **Strict Grouping Key**:
  `groupKey = (saProjectId, saEmployeeId, workDate)`
  Only rows possessing a valid, non-empty `saEmployeeId` participate in employee grouping.
- **Missing `saEmployeeId` Rule (CRITICAL)**:
  - For structured P2P submissions, any row without `saEmployeeId` MUST become `identity_conflict`/`unresolved`.
  - **NEVER** auto-link by number or name. Even if two rows from different Minis share the identical `number` and `name`, they remain separate unresolved items requiring explicit user resolution.
- **Non-Deletion Rule**:
  - A missing row from another Mini never means absent or deleted.
  - If Mini A submits hours for an employee and Mini B does not mention that employee, the employee's attendance from Mini A stands as reported.
- **Hours Conflict Detection**:
  - If multiple Minis submit records for the same `(saProjectId, saEmployeeId, workDate)` with differing `normalHours` or `overtimeHours`, the item is flagged as `conflict` (`conflictType: 'hours_conflict'`) with hours set to `null` pending human choice.
- **Complete Provenance Preservation**:
  - Every consolidated item retains its full `sources` array documenting each contributing Mini: `submissionId`, `deviceId`, `sourceId`, `capturedAt`, `rosterVersion`, `miniLocalId`, `number`, `name`, `normalHours`, `overtimeHours`.
- **Review Grouping Modes**:
  - `byDay`: Groups items by `workDate`.
  - `byPeriod`: Groups items across the date range by `saEmployeeId` and exposes unresolved identities separately.

## 5. Proposal Seam for Existing Resolver

- `buildConsolidationProposal(consolidation, { employees, attendance })`:
  - Compares consolidated items against existing SA attendance in `state.attendance`.
  - Classifies each proposal as:
    - `matched_existing`: Equal hours to existing SA record (no diff).
    - `conflict_existing`: Different hours from existing SA record (diff tracked).
    - `ready_new`: New record to create.
    - `blocked`: Blocked by unresolved identity or cross-Mini hours conflict.
  - Sets `canAutoApply: false`.
  - **NEVER** writes directly to `state.attendance`.

## 6. UI Choice in `MiniAttendanceImportModal`

- **Initial Screen**:
  Offers a tabbed selector: **Conectados** vs **Pegar texto**.
- **Pegar texto**:
  Preserves 100% of the existing human-readable WhatsApp parser, step-by-step setup, date confirmation, allocation mode, and individual review workflow.
- **Conectados**:
  - Linked Mini device selector (`data-mini-connected-selector`).
  - Day vs Period grouping toggle (`data-mini-grouping="day"`, `data-mini-grouping="period"`).
  - Date inputs (`data-mini-date-input` for day; `data-mini-range-start` and `data-mini-range-end` for period).
  - Clean callback/service seam (`onRequestSubmissions` / `data-mini-action="fetch-connected"`) to request submissions without touching `P2PCore`.
  - Saved Draft List from `AttendanceSubmissionInboxStore` (`data-mini-saved-drafts`).
  - "Consolidar seleccionados" action (`data-mini-action="consolidate-drafts"`).
  - Consolidation Review Skeleton (`data-mini-consolidation-skeleton`) displaying summary metrics, grouped items by day or period, and the proposal seam banner.
